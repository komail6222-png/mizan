# Qualification record | local CPU release

Updated for release 3.1 (the Hugging Face evaluation and the redesigned interface) and release 3.0. Changes and their evidence are in `docs/RELEASE_3.1.md`, `docs/RELEASE_3.0.md`, `docs/RELEASE_2.3.md` and `docs/RELEASE_2.2.md`. Safety evidence is in `reports/safety/safety.json`. A visual summary of the evaluations is `reports/evaluation/index.html`, and of the Hugging Face comparison `reports/evaluation/models.html`.

The bundled results come from one local host, one operator trust domain and generated inputs. A passing application test may exercise part of an architectural acceptance case. The counts in those two sets have different meanings.

A 2.2 rerun on Python 3.13.18, NumPy 2.5.3 and SciPy 1.18.1 reproduced SANAD and BASIRA exactly and RASID forecasts exactly. RASID's arithmetic oracle uses a two-hour battery and a tariff where raising the peak can lower total cost. The independently checked optimum in the fixture costs 2 and imports [2, 0] kW. Units in cost tables are illustrative. The simulation does not connect to hardware.

## Operating boundary

The local broker owns its SQLite database, CAS, trust root and generation. A local write token grants operator access. Workers run trusted code as the same OS user. The process limits constrain ordinary computation. A production threat model that includes malicious workers requires OS identity separation, restricted filesystem mounts, egress policy and protected signing keys. Keep secrets and runtime databases outside public exhibits. The distributed design, detailed numerical gates and proposed memory fallback ladders are specified in `docs/history/MIZAN_Final_Codex_Brief.md`.
